Adapter protocol & comparison boundaries

AVAILABLE · v0.3.2

Full-state integration

Each episode creates a fresh adapter with reset(context), act(state) and close(). Actions are normalized steering and throttle/brake at 0.1 s control steps.

The adapter receives privileged simulator state and supplies its own observation filter, planning and tracking. Camera and BEV clips on this page are visualizations, not the current online policy input.

NOT PROVIDED AS A STANDARD TRACK

Information-limited comparison

A common restricted-observation contract is not enforced by the current standalone adapter. Full-state access can bypass the intended information-availability challenge.

To compare that capability, first agree on and enforce the same visible fields, range, history and update timing for every planner. A planner’s self-selected filter alone does not establish an equivalent information boundary.

For comparable experiments: use the same exported scene suite, observation contract, control interval, horizon and termination rules; report planner randomness and controller settings. Treat full-state and restricted-observation experiments separately. The current package offers integration and basic evaluation, not a standardized information-limited ranking.
03 Installation, batch runs & downloads

Install & reproduce a scene

01 / INSTALL

Clone and install

Use Python 3.11 in a separate environment. These commands use a macOS/Linux shell.

git clone https://github.com/xypeng12/driving-exceptions-benchmark.git
cd driving-exceptions-benchmark
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install '.[simulation]'

The simulation extra installs MetaDrive 0.4.3 and GIF support. Geometry-only export can use python -m pip install ..

02 / GENERATE

Reproduce a configuration

List all 14 preset configuration groups, then export one S1-01 instance from the bundled environment YAML.

driving-benchmark list

driving-benchmark export \
  --config src/driving_benchmark/data/scenario_outline.yaml \
  --scene S1-01 \
  --output generated/s1-first

The output is generated/s1-first/scene.json. Replace the config path with your own compatible outline. Generation does not start MetaDrive; existing output directories are refused.

03 / PREVIEW

Start the native scene

Run a short S2-01 preview and save the scene, actual truth trajectory, basic metrics and an optional BEV GIF.

driving-benchmark preview \
  --scene S2-01 \
  --steps 20 \
  --output generated/s2-basic \
  --bev-gif generated/s2-preview.gif

The new directory contains scene.json, trajectory.json and metrics.json. Twenty control steps cover two simulated seconds with fixed braking input; this is an environment check, not an autonomous recovery demonstration. Add --render for a native 3D window on a supported desktop.

04 / EVALUATE

Evaluate the saved trajectory

Reproduce all four metric groups offline from the files recorded in the previous step.

driving-benchmark evaluate \
  --scene-file generated/s2-basic/scene.json \
  --trajectory generated/s2-basic/trajectory.json \
  --output generated/s2-metrics.json

This command starts no simulator or policy. The report covers task, safety, authorization and progress/time; it binds the exact scene and trace identities and refuses existing output files. The short preview will normally remain noncompleted/censored.

Batch sampling & your own planner

Create a fixed suite, run the same scene instances with your own planner, then regenerate all four metric groups offline.

1. Set seeds and count per group

Save this as sampling.yaml. Count is per seed: this example generates 8 scene instances (2 × 3 + 1 × 2). Include all fourteen group IDs to sample the full configuration catalog.

format: driving-exceptions-sampling-v1
groups:
  - scene: S1-01
    seeds: [0, 1]
    count: 3
  - scene: S2-01
    seeds: [0]
    count: 2
driving-benchmark sample \
  --plan sampling.yaml \
  --output generated/shared-suite

Optional --config my_outline.yaml changes environment parameters. The suite preserves each materialized scene and its identity. Default dev seeds are 0–9; instance indices are 0–99. Seeds vary only the quantities implemented by each family.

2. Connect, run and re-evaluate

Install your own Python adapter exposing create_planner(). Each episode uses a fresh adapter with reset(context), act(state), and close(). Act returns normalized steering and throttle/brake; your adapter supplies observations, planning and trajectory tracking.

driving-benchmark run-suite \
  --suite generated/shared-suite \
  --planner my_adapter:create_planner \
  --max-steps 3000 \
  --output generated/my-run

driving-benchmark evaluate-suite \
  --run generated/my-run \
  --output generated/reevaluated

Run serially at 0.1 s control steps. Outputs include per-instance scene, trajectory, metrics and errors, plus overall and per-group summaries. Offline evaluation starts no simulator or planner. The included fixed-brake adapter is for wiring checks only.

Comparison scope. Every planner should use the same exported suite. The adapter receives privileged simulator state and owns its observation filter, controller and random seeds. Completion rate includes all planned instances; failures and missing traces stay explicit. Violation counts use evaluated traces only. Runs stop at the goal, native termination or simulation-step limit; there is no forced wall-time timeout. Full adapter protocol, outputs & limits ↗
Generate multiple instances. In Python, use the same group with a different seed or instance index (0–99). For example:
from driving_benchmark import generate_scene

scene = generate_scene("S1-01", seed=7, instance_index=3)

For controlled traffic variations, edit the bundled YAML’s traffic parameters and pass that file as config=.... Seeds sample only the random quantities implemented by that family; they do not randomize every parameter. Keep the configuration, seed, instance index and exported scene identity with evaluation results, and use the same exported scene across planners.

Package scope. Includes configuration validation, deterministic scene generation, native road/traffic/event logic, a raw-control AV interface, truth recording, serial batch integration and the four basic metrics. It excludes the research agent, planner, model services, policy-specific diagnostics and research-specific evaluator. Exported setup and runtime state are privileged simulator data; integrators provide their own policy observation layer. Full usage guide ↗
